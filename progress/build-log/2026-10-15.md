# Build log — 15 October 2026

Scope: build the working single-page application from the three primary specifications ([brief](../../context/briefs/2026-10-15-runtime-application-build.md)). Results below are what was actually run and observed; limitations are listed at the end.

## Built

- **Application** (Next.js 16 App Router, React 19, Tailwind 4, Motion, three.js/react-three-fiber, pdf.js, pdf-lib): 3D hub plus nine workspaces, Templates and Feedback in one page; URL keeps the screen and version (`?s=review&v=…`). Design frame of 1536 × 1024 scaled to the viewport on desktop; flow layout below 900 px wide.
- **Supabase**: three migrations (schema + RLS + storage + Realtime; annotation agent/help columns; worker endpoint registry).
- **Review pipeline**: PDF extraction with page geometry and real font names (pdf.js with `fontExtraProperties`), Word inspection (mammoth + `word/*.xml`), conversion comparison, rules, semantic adapter, evidence validator, decision-agent routing/ordering, field detection with content-based transfer.
- **Digitisation**: annotation editor and QA, full-content form model, responses with autosave, PDF fill with clipping detection and four read-back QA checks, review report PDF.
- **Worker**: FastAPI service with Laya (`predict` and batched `predict_batch`) and Word conversion (Word COM on Windows, LibreOffice in Docker); Supabase-session authentication; local runner with Cloudflare quick tunnel, URL publication and watchdog.
- **Blender**: nine stations built by script, exported to GLB, rendered live in the hub with hover cues and the station-to-header flight.

## Security review follow-up

An automated review flagged two issues; both were fixed and re-verified on production:

1. *Worker endpoint registry*: an anonymous caller could have claimed an unclaimed endpoint and redirected worker traffic. The endpoint had already been claimed by the owner's run; the claim function was dropped, `set_worker_url` now requires the seeded hash and a `*.trycloudflare.com` host, and the app checks the same host pattern before sending a session token.
2. *Word automation on untrusted files*: macro-enabled packages are rejected, external relationships other than hyperlinks are stripped, and Word runs with macros forced off and no prompts. `worker/test_sanitize.py` passes. A production upload afterwards converted in 13.6 s and produced the expected findings.

An automated security review of the follow-up commit flagged that any anonymous session could call the worker's `/semantic` endpoint directly, using the owner's CLI quota outside the app's hourly limit. Fixed in the worker: per-session (12/hour) and global (60/hour) caps, index size limit, and workspace feedback moved into a delimited data section. `worker/test_semantic_quota.py` and `worker/test_sanitize.py` pass. A shared-secret requirement was not used because the Vercel environment could not be changed from this session. A second review of that fix noted that the cap was keyed on the token string (a refreshed token reset it), that clearing the map could reset the global window, and that check-and-record was not locked; the worker now keys the cap on the verified Supabase user id, keeps the global window separately, evicts only expired per-user windows and records under a lock. Both worker tests pass again; unauthenticated `/semantic` returns 401.

A further automated review found that the regular-expression sanitizer only removed external relationships written exactly as `TargetMode="External"` in self-closing tags; other quoting, spacing, casing or paired tags, `file:`/UNC targets and remote-loading field codes could reach Word (remote template fetch, NTLM credential leak). The sanitizer now parses each part with an XML parser after an expat pass that refuses DOCTYPE/ENTITY in any encoding, keeps only internal targets and http(s)/mailto hyperlinks, and rejects INCLUDEPICTURE/INCLUDETEXT/LINK/DDE/DDEAUTO/IMPORT fields; Word converts with link and field updates off. Checks: `worker/test_sanitize.py` passes (quoting/casing variants, paired tag, `file:` and UNC targets, UTF-8 and UTF-16 DTDs, split INCLUDEPICTURE, DDEAUTO, unparseable `.rels`, macros, clean document); both demo `.docx` files pass the sanitizer and convert in Word (rc 0, 12.9 s); with `UpdateLinksAtOpen` set to True before a conversion it read True afterwards, then was set back to the machine's original False.

A third review noted that checks were chosen by file name (a document part not named `.xml` skipped the field check), that altChunk imports, embedded objects and HTML/RTF parts were not blocked, and that the field denylist missed Strict-namespace and nested fields. The sanitizer now dispatches on `[Content_Types].xml`, allowlists relationship types, non-XML content types (images, fonts, printer settings) and field keywords, matches elements by local name in any namespace, tracks nested complex fields, and rejects `fldData`, mail merge, altChunk, sub-documents and objects. `worker/test_sanitize.py` covers these cases and passes. Regression check against real Word output: the demo re-saved by Word and a Word-built document with header/footer PAGE and NUMPAGES fields, table of contents, hyperlink, table, footnote, comment and picture both pass and convert (rc 0; 9.8 s and 15.5 s).

A fourth review found parser differentials: attributes matched by local name (a foreign-namespace `x:Type` listed first could hide the `Type` Word reads), field markup accepted in any namespace, empty instructions and instruction text after the separator accepted, and parts declared as images not checked even when they contain XML. While fixing these, a further gap was found: a field whose keyword comes from a nested field's result (`{ {REF x} PAGE }`) would have passed. Now: exact qualified attribute names, field markup only in the Transitional/Strict WordprocessingML namespaces (look-alikes rejected), strict field parsing (non-empty instruction, no keyword from a nested field, no instruction after the separator), allowlisted binaries that hold XML checked as XML, relationship targets must have a content type that fits the relationship type, and SVG images and `file:`/UNC/network attribute values rejected. `worker/test_sanitize.py` covers each case (including a legitimate nested `IF … { PAGE }`, which passes). Word regression: the Word-saved demo, the Word-built document with headers, fields, TOC, footnote, comment, table, hyperlink and picture, and demo v2 all pass and convert (rc 0; 11.8 s, 79.0 s and 64.3 s — slower than earlier runs on the same files, likely Word start-up contention on the owner's machine).

A fifth review noted that the path check missed drive letters, mixed separators and whitespace/percent-encoded values, and that relationship targets resolving to a missing part were skipped (fail open), with percent-decoding that could differ from Word. Now values are normalised before matching (drive letters, `file:`, UNC and `/\` forms), linked-picture `href`/`src` attributes are refused outright, internal targets must name an existing part written without `%`, `?`, `#` or backslashes, and part names with those characters, empty/`.`/`..` segments or case-insensitive duplicates reject the package. `worker/test_sanitize.py` covers each case and passes; the Word-saved demo, the Word-built rich document and both demo files still pass and convert (rc 0; 15.3 s, 34.0 s, 11.4 s, 8.8 s).

A sixth review noted that only attributes named exactly `href`/`src` were refused (VML also has `o:althref` and others) and that URL values in other attributes passed. Now any attribute whose name ends in `href` or `src`, and any URL-like value (`scheme://`, `mhtml:`, `ms-…:`, `javascript:`, …) is refused, except `uri` attributes holding the schema identifiers Word writes on every picture (`http://schemas.openxmlformats.org/…`, `schemas.microsoft.com`, `purl.oclc.org`). Tests pass; the four real documents still pass and convert (rc 0; 29.7 s, 102.4 s, 37.4 s, 7.5 s — conversion time varies widely on the owner's machine).
